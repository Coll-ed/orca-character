# 卡死二分方案（预置 · 2026-10-04）

> **为什么预置**：交接文档 `05-文档\⑤` 的一句操作纪律是「**改—编译—不改善就回滚**」，
> 而它的教训表里第一条是「不看编译结果就改逻辑 ⇒ 两轮里把错误数从 45 弄到 104」。
> ⇒ 卡死这种"无异常、无堆栈"的问题，**必须先想清每一步，再动手**，否则就是又一次兜圈。
>
> 本文把两种可能的反馈对应的动作**事先写定**，这样一有结果就能立刻执行。

## 一、每次实验的固定纪律（不可省）

```
1. 一次只改一个变量
2. 编译必须 0 错误（改前后都记警告数）
3. 【dll 与 pck 同步产出】—— 不得混用（自建 dll 配官方 pck / 官方 dll 配自建 pck 都不行）
4. 部署后记录双份来源与哈希（dll sha256 前 16 位 + pck sha256 前 16 位）
5. ★ 每个实验版本带【唯一版本标记】，启动时打进日志
   —— 用来确认"用户实际跑的确实是这一版"
   （交接文档⑤ 教训表第 6 条：曾同时存在 src / src-s2 / src-fresh 三棵树，从错误的树编译了一整轮）
6. 结果只有两种：卡 / 不卡。不改善 ⇒ 立即回滚该变量，再试下一个
```

**版本标记的实现方式（一次性加好，后续只改标记值）：**
在 `OrcaBootstrap` 启动路径上加一行
`OrcaLog.Info("[Orca] 构建标记 = <标记>", 2);`
⇒ 每次实验把 `<标记>` 换成如 `EXP-B1-no-cardui-refresh`，从日志即可确认加载的是哪一版。

## 二、分支 A：用户反馈【不卡了】

**结论**：真因在那 12 个手写化文件里，是某个"机器痕迹"引起的。

**二分顺序（先查最可疑的，不要按清单顺序）：**

| 步 | 动作 | 理由 |
|---|---|---|
| **A1** | **只把 `Core\OrcaCard.cs` 恢复成改写前版本**（`git show <改写前的提交>:...`） | 它是 12 个里**唯一含 `<>n__0` 编译器转发器**的；而且在**出牌链路上**（`AfterCardPlayed`） |
| A2 | 若 A1 复现卡死 ⇒ **答案就是它** ⇒ 精确到"哪一处改写" | 在 A1 基础上逐段恢复（注释 → 常量 → 枚举名 → 强转） |

**⇒ 关键：分支 A 的每一步都**不会**引入新逻辑 —— 只是把"手写版"换回"反编译版"。所以无论结果如何，都能干净地回滚。**

## 三、分支 B：用户反馈【还卡】

**结论**：卡死与那 12 个文件无关（它们已逐字方法级对照等价）。**靶子在别处。**

### B.1 出牌链路上仍然活着的嫌疑（按嫌疑度排序）

```
① OrcaCardUi.Refresh(...)      —— 手动重绘卡面文字,在 OnPlay 里被直接调用
② OrcaEnergyCounter（602 行）   —— 日志显示它【每帧都在跑】(多条 <120ms 节流日志)
③ OrcaFrenzyCard               —— 狂躁基类(HasTurnEndInHandEffect / IsFrenzyPlay)
④ ModelDb 三个 getter 的 Postfix —— AllCards / AllCharacterCardPools / AllRelicPools（A4 强耦合）
⑤ A2/A3 两个关着的开关          —— 保持关闭 = 与官方一致；开启后行为未验证
⑥ C4 治疗加成                   —— 已改为 BaseLib IHealAmountModifier，未验证
```

**已排除（不要再查）：**

```
✗ 台词/气泡链路 —— OrcaSpeech.SayCardType / SayCardLine 都是 void（非 async）；
                   频率档门控在方法第一行 ⇒ off 时在引擎 TalkCmd.Play 之前就 return
                   ⇒ 用户那次"气泡 off 仍卡死"是有效否证
✗ OrcaCard.AfterCardPlayed —— 与官方 dll 逐字方法级等价
✗ B2：8 个 Harmony 补丁打空 —— 目标在当前 sts2.dll 里全都存在；实测 41 成功 / 0 失败；
                               OrcaBootstrap 是逐类独立 try/catch，本就不会级联
✗ Canonical model 卫士 —— 出现在百科看卡面时（规范模型无 Owner），代码已捕获回退；
                           全工程 44 处 ModelDb.Card<> 用法全部正确
✗ 21 条素材加载失败 —— 根因是那些 .tres 首行缺 `]`；且【确证不该修】（见汇总文档第二节）
```

### B.2 二分步骤（每步一个变量，用户打一张牌即可判定）

**★ 顺序原则：先关掉"我们自己加的、每帧/每张牌都会跑的东西"，再动数据层。**
**因为卡死形态是「OnPlay 日志全出来之后静默停住」⇒ 优先怀疑 OnPlay 之后、或与 OnPlay 并发的每帧逻辑。**

| 步 | 动作 | 预期判据 |
|---|---|---|
| **B1** | 在 `OrcaCard.OnPlay` 之后**不再调用** `OrcaCardUi.Refresh(...)`（把该调用整段注释，保留函数本体） | 若不再卡 ⇒ 凶手是"手动重绘卡面"这条链 |
| **B2** | 关掉 `OrcaEnergyCounter` 的每帧刷新（只留构造时的那次） | 若不再卡 ⇒ 凶手是能量球每帧逻辑 |
| **B3** | 把 `ModelDb.AllCards` / `AllCharacterCardPools` / `AllRelicPools` 三个 Postfix **暂时整段 return true**（不注入） | 卡池/进局路径的枚举注入（A4 强耦合）。注意：百科可能因此少显示卡 ⇒ 属预期副作用 |
| **B4** | 把 `OrcaFrenzyCard.IsFrenzyPlay` 恒返回 false（狂躁不触发） | 若不再卡 ⇒ 凶手在狂躁的"回合结束自动打出"链 |
| **B5** | 打开 `A2`（`break` → `continue`，即恢复 C2 的第一处） | 注意：**这是引入"原始版没有的行为"** ⇒ 只有在 B1–B4 全部否证后才试 |
| **B6** | 打开 `A3`（`molten` 判据） | 同上 |

**⇒ 每一步都：编译 → 部署（dll+pck 同步）→ 记哈希与版本标记 → 用户打牌 → 卡/不卡 → 不改善立即回滚。**

### B.3 若 B1–B6 全部否证

**⇒ 说明凶手在"我们自己加的、但不在上述清单里"的逻辑中。此时改用**排除法**而非二分法：**

```
分步停用整个子系统（每次停一个,各自独立可回滚）:
  1. 停用 OrcaSpeech 的全部调用（含 SayEvent / SayCapped）
  2. 停用 OrcaKeyword 的"按文案自动挂浮窗"机制
  3. 停用 OrcaAudioPatch（我们自己的音频接管）
  4. 停用 OrcaCharacterIcon / OrcaSkin 的皮肤系统
  5. 停用 OrcaPoolRegistry 的全部 Harmony 补丁（退回"不注册"状态）
⇒ 停到哪一步不卡了,凶手就在那个子系统里
```

**★ 另外一条独立验证路线（更强、但需要用户配合更多）：**
