{
    // ① 消耗当前所有的手牌（权威 L40）。不含本卡自己 —— 它正在被打出 …

    await PowerCmd.Apply<OrcaOverlookPower>(ctx, Owner.Creature, n, …);     // ④ 等额层【睥睨】

## 四、边界：手牌为 0 时怎么办（★ **待用户确认**）

权威 L40 只写了"消耗当前**所有**的手牌…等额…"，**没有规定手牌本来就空的情况**（本卡打出时若手牌里没有别的牌）。

**选择：整条效果不发生**（不抽牌 / 不附加焚烧 / 不获得【睥睨】），并**显式记 WARN**（`Cards-Pack2-B.cs:87-95`）：

```csharp
if (n == 0)
{
    OrcaLog.Warn("[Orca] 睥睨：手牌中没有其它牌 ⇒ 本次不抽牌、不附加【焚烧】、不获得【睥睨】"
               + "（权威未规定此边界，暂按「整条效果不发生」处理，待用户确认）", 2);
    return;
}
```

理由（三条，可复核）：
1. **n = 0 时三个效果都是空操作**：抽 0 张无意义、给敌人各 0 层焚烧无意义、给自己 0 层【睥睨】无意义；
2. 若照常调用 `PowerCmd.Apply<OrcaOverlookPower>(…, 0, …)`，**会在 buff 栏挂一个 0 层的空图标**（`StackType.Counter`），玩家会看到一个"不存在却占位"的 buff ⇒ 明确的坏表现；
3. 掷异常不可取：**手牌为空时打出这张牌是合法操作**（例如它就是手里最后一张），抛异常会中断出牌流程、破坏战斗状态机。

⇒ 这是"选一个合理且显式记日志的行为"，**不是权威结论**：请用户确认"手牌为 0 时应该整条无效果（本实现），还是仍要有某种保底效果（例如至少给 1 层【睥睨】）"。确认后只需改 `Cards-Pack2-B.cs:87-95` 这一段。

**另一个需要留痕的读法选择（同一处）**：`n` **不含本卡自己**（`!ReferenceEquals(c, this)`）。理由：本卡正在被打出，引擎是否已把它移出手牌**随版本/时序而定**；显式排除后两种时序下口径一致（"当前所有手牌"不把正在打出的这一张算进去）。这与原版同类效果（如"消耗你的手牌"）一致。若用户认为应当把本卡自己也算进"等额"的 n，改这一行的过滤条件即可（同样列**待确认**，但优先级低于上一条）。
