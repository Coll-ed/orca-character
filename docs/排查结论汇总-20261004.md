### ★ 两条容易被误判为"反编译残留"的东西（官方 dll 里同样存在）

| 形态 | 真相 |
|---|---|
| `private Task <>n__0(...)` / `_003C_003En__0(...)` 转发方法 | **Roslyn 对「async 方法里调用 `base.`」生成的必需转发器**。手写 `await base.X(...)` 后编译**同样**会生成它 ⇒ 不要删 |
| `DefaultInterpolatedStringHandler` + 一串 `AppendFormatted` | **编译器对字符串插值的正常降低产物**。手写插值后反编译出来还是它 ⇒ 不要当成垃圾 |

**⇒ 通用判据：遇到奇怪的生成物，先反编译官方基准 dll 看它有没有；有就别动。**

## 二、★ 21 条 `素材加载失败（相关配色会退回默认）` —— 根因确证，且**确证不该修**

**现象：** 日志里 21 条
`[WARN] [Orca] 素材加载失败（相关配色会退回默认）：res://images/atlases/power_atlas.sprites/orca_*.tres`

**已排除：** 文件本身存在 ✓ / 引用的 `.png` 存在 ✓ / 该 png 的 `.ctex` 存在 ✓ /
`.tres` 里的 uid 与 `.import` 的 uid **逐条一致** ✓ ⇒ **不是缺资源，也不是 uid 造假。**

**真因（逐字比对确认，完全吻合）：** 这些 `.tres` 的**首行少了闭合的 `]`**：

```
正常: [gd_resource type="AtlasTexture" load_steps=2 format=3 uid="uid://corcalifestealspr"]      ← 有 ]
坏的: [gd_resource type="AtlasTexture" load_steps=2 format=3 uid="uid://corcavoidreturnpower"    ← 缺 ]
```

```
统计：power_atlas.sprites 下 30 个 .tres 中，缺 ] = 21 个 / 有 ] = 9 个
日志：失败清单 21 条
比对：交集 = 21 条（不多不少）
```

**⚠️ 但【不能修】—— 两个文档都记着这条血泪：**

> `05-文档\②` D5：verify 套件有 4 条 `KNOWN_DEVIATIONS`（`.tres` 缺 `]` / ctex 头不符 /
> PNG 尺寸不符 / 卡面命名不符）—— **都是原始包本来的形态** ✓，"修好它们"曾在
> 2026-09-30 **把百科搞崩** ✗ ⇒ **动它们必须单独实测**。

> `05-文档\①`：**把 `.tres` 缺 `]` 当根因并宣布"已修复"** —— 后来证明原始版带着这些解析错误
> 照样能开百科；而"补上 `]`"反而**把一批「UID 失效但可加载」的资源送进预载缓存 ⇒ 崩溃**。

**⇒ 机制：缺 `]` ⇒ 解析失败 ⇒ `ResourceLoader.Load` 返回 null ⇒ **不进预载缓存** ⇒ 下游不炸。**
**⇒ 补上 `]` = 让 21 个此前被跳过的资源全部进缓存 ⇒ 重演那次崩溃。**
**⇒ 处置：保持原样。这条警告是**设计代价**，不是待修的缺陷。**

```
❌ A3  OrcaBurnAndEcho.cs:67        bool molten = false; /*TOGGLE-OFF-A3：判据暂时短路，验完恢复*/
❌ A2  OrcaBurnAndEcho.cs:109       /*TOGGLE-OFF-A2*/ break;      （应为 continue）
```

**⇒ 这三个**保持关闭**，理由不是省事：**

**验收判据是「行为与官方基准一致」= 与**原始 dll** 一致。而 `05-文档\②` 的 C2 明确记载，
原始版里这三处**本来就是坏的**（`break` 而非 `continue`、没有 `if (molten)` 分叉、
给牌不进牌组）。**

```
保持关闭 = 与官方基准行为一致 ✓  ← 判据要求
打开它们 = 引入原始版没有的行为，且从未验证过
⇒ 在卡死未定性之前打开 = 往未定变量上再加变量，违反"一次只动一个变量"
```

**⇒ 结论：留到卡死定性之后，作为独立功能项一个一个开、一个一个验。**

## 六、方法学（本轮验证过、值得沿用的）

1. **枚举名化可以用"编译回来仍是同一个数字"来反证**：
   把 `(TargetType)2` 写成 `TargetType.AnyEnemy` 后编译，反编译回来仍是 `(int)v != 2` ⇒ 语义未变
2. **扫描器要剔除注释行**：我在注释里引用 `_003C_003E` 等词解释改动，导致首轮扫描 11 个文件误报
3. **改写时"顺手加个空判断"就是引入行为差异**：
   `ShouldTakeExtraTurn` 我多写了 `player != null &&`，而原式在 `player == null` 的边界上结果相反
   ⇒ 改成严格等价的 `player == owner?.Player`
4. **验证"回滚成功"的判据必须是外部基准**：我曾拿"部署 == 我自己的中间存档"当回滚成功，
   而那份存档里的 pck 本来就是自建的 ⇒ **等于自证**。必须用官方基准的哈希做判据
5. **不要在会阻塞的命令里放网络重试**：一次 `git push` 重试 4 次 + sleep 会让整条命令挂 6 分钟
