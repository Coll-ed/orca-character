## 1. 验证过的引擎机制（全部有反编译实据）

### 1.1 ★★★ 卡牌关键词**只算一次就缓存** ⇒ 不能在 `CanonicalKeywords` 里判 `IsUpgraded`

```csharp
// MegaCrit.Sts2.Core.Models.CardModel —— LocalKeywords
private HashSet<CardKeyword> LocalKeywords {
    get {
        if (_keywords != null) return _keywords;      // ← 之后永远吃缓存
        _keywords = new HashSet<CardKeyword>();
        _keywords.UnionWith(CanonicalKeywords);       // ← CanonicalKeywords 只读这一次
        return _keywords;
    }
}
```

`CardModel` 自己给的文档口径：*"its canonical keywords, plus any added by `AddKeyword`,
minus any removed by `RemoveKeyword`. This is the persistent, instance-owned keyword state"*。

- **症状**：敲后卡面**照样显示「消耗」**（玩家截图实锤：焚卷入典+/红莲淬+/睥睨+）。
- **错误写法**（我们踩过，一字不差）：
  ```csharp
  public override IEnumerable<CardKeyword> CanonicalKeywords
      => IsUpgraded ? Array.Empty<CardKeyword>() : new[] { CardKeyword.Exhaust };
  ```
- **正确写法**：基础集合**静态**，敲后走移除：
  ```csharp
  public override IEnumerable<CardKeyword> CanonicalKeywords => new[] { CardKeyword.Exhaust };
  protected override void OnUpgrade() => CardCmd.RemoveKeyword(this, CardKeyword.Exhaust);
  ```
- **推广**：凡是"由实例状态派生的只读集合/属性"，都要先问一句**引擎什么时候求值、会不会缓存**。

### 1.2 ★★ Harmony **不会 await**：`async` 方法上的 Postfix 时机不可靠

```csharp
// TouchOfOrobas
public override async Task AfterObtained()          // async Task、无参数
{
    ...
    await RelicCmd.Replace(relicById, replace);
}
```

- Postfix 在**方法刚被调用（第一个 `await` 之前）**就跑 ⇒ "它做完之后我再做"这类假设**全部不成立**。
- **正确做法**（本轮采用）：若原方法**只做一件事**，用 **Prefix 返回 `false` 整段跳过**，
  自己的逻辑写进 Prefix —— 既达成目的，又彻底绕开 await 时序问题。
- **注意**：用 Prefix 跳过前**必须逐行确认原方法没干别的必要的事**（本轮核过：只有一次 `RelicCmd.Replace`）。

### 1.3 ★★ "显示值"与"真值"必须同源：`PowerModel.Amount` vs `DisplayAmount`

```csharp
public int Amount { get => _amount; private set => SetAmount(value); }   // ★ private set —— 外面改不了
public virtual int DisplayAmount => Amount;                              // 引擎留的"只改显示"的口
// 浮窗文案用的是它：
locString.Add("Amount", Amount);
```

- **我们踩的坑**：烧牌加成存在**自己的私有字段**里，结算读"Amount + 私有字段" ⇒
  **效果生效、但图标与浮窗永远显示 `Amount`（常驻 20）**，玩家看不到它涨。
- **两条路，选对的那条**：
  | 方案 | 结果 |
  |---|---|
  | 覆写 `DisplayAmount` | 图标变了、**浮窗还是旧的** ⇒ 两处不一致 ✗ |
  | **让 `Amount` 本身成为真值** | 图标 / 浮窗 / 结算**三处同源** ✓ |
- **改量必须走公开入口**（`Amount` 是 `private set`，硬写会 `CS0200`）：
  ```csharp
  // 引擎实现：int newAmount = power.Amount + (int)modifiedOffset; power.SetAmount(newAmount, silent);
  await PowerCmd.ModifyAmount(choiceContext, power, offset, applier, cardSource);
  ```
  ⇒ 它内部走 `SetAmount`（**会通知 UI**，图标才会刷新）。
- **教训**：**先找引擎的公开改量/改状态入口，再考虑"自己加个字段"** —— 自己加字段几乎必然与 UI 脱钩。

### 1.4 ★ 奖励体系是**类化**的（改奖励 = 换类，不是改数值）

```
Reward（基类）
 ├─ RelicReward          ← 遗物格
 ├─ CardReward           ← 普通卡牌奖励
 ├─ SpecialCardReward    ← 「给一张指定卡」：SpecialCardReward(CardModel card, Player player)
 ├─ GoldReward / PotionReward / CardRemovalReward
 └─ RewardsSet / LinkedRewardSet（一组奖励的容器）
```

- **`SpecialCardReward` 的语义就是我们要的**（引擎原文）：*"A reward that adds a specific card
  to the player's deck. Good for events like `TheLanternKey` that give specific quest cards…"*
- ⚠️ **`RelicCmd.Obtain` / `RelicCmd.Replace` 不创建任何 `Reward`**（只是 `await relic.AfterObtained()`）
  ⇒ **"遗物格"不是从遗物命令来的**，别去那儿找。

### 1.5 ★★ 先古事件的遗物是「**事件选项**」，不是奖励格

```csharp
// MegaCrit.Sts2.Core.Models.Events.Orobas —— OptionPool3
TouchOfOrobas touchOfOrobas = (TouchOfOrobas)ModelDb.Relic<TouchOfOrobas>().ToMutable();
if (touchOfOrobas.SetupForPlayer(base.Owner))
    list.Add(RelicOption(touchOfOrobas));          // ← 那一格
ArchaicTooth archaicTooth = ...;                   // 古老牙齿在同一池
```

- **先古事件发生在打完 Boss 之后** ⇒ 玩家口中的"战后奖励界面"其实就是**它的选项页**。
- `EventOption` 的结构（决定能改成什么）：
  ```csharp
  public RelicModel? Relic { get; private set; }   // ★ 有它才渲染成"遗物格"
  public EventOption(EventModel eventModel, Func<Task>? onChosen,
                     LocString title, LocString description, string textKey, IEnumerable<IHoverTip> hoverTips);
  ```
- ⚠️ **`EventOption` 没有 `Card` 图形位** ⇒ 换出来只能是**文字选项**，换不出"卡面格"。
  想要卡面渲染得先确认引擎有没有别的渲染位（本轮确认没有）。

### 1.6 篝火角色按**章节**播动画（"当前第几章拿不到"是错的）

```csharp
// NRestSiteCharacter._Ready
string animName = Player.RunState.CurrentActIndex switch {
    0 => "overgrowth_loop", 1 => "hive_loop", 2 => "glory_loop",
    _ => throw new InvalidOperationException("Unexpected act") };
foreach (var childSpineNode in GetChildSpineNodes())
    this.RunWhenSpineReady(new MegaSprite(childSpineNode), a => a.SetAnimation(animName));
```

- `Player` 是**公开属性** ⇒ 章节拿得到；三个动画名与 `skins/orca/*/skin.json` 的
  `rest.act0/act1/act2` **完全一致**。
- 角色场景里写的是 `preview_animation = "-- Empty --"` ⇒ 动画**全靠代码设**，
  换骨架后必须自己驱动一次（否则"换成奥卡但静止"）。

### 1.7 治疗入口不唯一：`CreatureCmd.Heal` **不是**唯一"回血"路径

- 我们 patch 了 `CreatureCmd.Heal` 做治疗加成 ⇒ **只覆盖走这条路的治疗**。
- `CreatureCmd.SetCurrentHp(me, me.CurrentHp + n)` 这类"直接加血"**绕开它**
  （魔剑单敌回血就是这么写的）⇒ 加成对它无效。
- **排查治疗相关问题时，先分清那次回血走的是哪条路**。

## 7. 追加（同一天晚些时候）：四条硬教训

> 这四条都是"改了才发现的"，代价分别是**一次卡死**和**一次误伤别的角色**，务必先读。

### 7.1 ★★★ 在事件回调里弹奖励界面 = **死锁**

- **现象**：事件选项点击后，奖励界面（`RewardsSet.Offer()`）**确实弹出来了**，
  但玩家点"领取"之后**整个界面卡死**、卡牌也没按流程进牌组。
- **根因**：`Offer()` 会 **await 玩家把奖励取走**，而它是在**事件选项的 `onChosen` 回调**里被调用的：

  ```
  事件流程 ──等待──> onChosen 返回 ──等待──> 奖励界面完成信号 ──等待──> 事件流程…
  ⇒ 互相等待 = 死锁
  ```

- **正确做法**：**事件回调里绝不 await 需要玩家交互的新界面**。
  要发奖励就找引擎认可的时机（例如事件关闭之后再发），否则**退回"直接进卡组"** ——
  **宁可少个动画，也绝不能卡死**。
- **推广**：任何 `await XxxScreen.Show()` / `await ...Offer()` / `await ...Select()` 之类的
  "等待玩家操作"的调用，放进另一个"正在等玩家操作"的流程里，都是一个死锁。

### 7.2 ★★ 奖励里必须传**可变实例**（`.ToMutable()`）

- **现象（日志实锤）**：
  ```
  [WARN] 发奖励失败 ⇒ 退回直接进卡组：
         Canonical model of type OrcaCharacter.OrcaHomestead used in incorrect place.
  ```
- **根因**：`ModelDb.Card<T>()` 返回的是 **canonical（模板）模型**，引擎拒绝把它用在奖励/牌堆这类
  "实例"位置。**症状极隐蔽**：不报错给你看，只是奖励流程静默失败（我们的兜底接住了 ⇒ 有牌、没动画）。
- **正确做法**：`ModelDb.Card<T>().ToMutable()` —— 引擎自己的惯例同此
  （`Orobas.cs` 里就是 `ModelDb.Relic<TouchOfOrobas>().ToMutable()`）。
- **推广**：凡是把模型交给引擎"放进某个容器/流程"的地方，先想一句**这是模板还是实例**。

### 7.3 ★★★ 静态字段指向 Godot 节点 ⇒ 节点被释放后引用**仍然非空**

- **现象**：皮肤面板的预览小人**偶尔会不见**；日志显示"建立/套皮"**都成功、无任何报错**。
- **根因**：Godot 节点被释放后，C# 侧的静态引用**不会自动变 null** ⇒
  守卫 `if (_previewSpine != null) return;` **永远提前返回、再也不重建** ⇒ 小人消失。
  （"偶尔"正是因为只有界面重建/节点回收之后才会发生。）
- **正确做法**：守卫必须判**有效性 + 是否还在树上**：
  ```csharp
  if (_previewSpine != null && (!GodotObject.IsInstanceValid(_previewSpine) || !_previewSpine.IsInsideTree()))
  { _previewSpine = null; /* 连同动画/皮肤标记一起重置 */ }
  ```
  重建入口放在**周期性刷新**里（本项目是 1 秒的 `SyncState`）⇒ 消失后下一轮自动长回来。
- **推广**：**任何缓存 Godot 节点的静态/长命字段，都要按这个模式写守卫**（面板、预览、注入的 UI 全部适用）。

### 7.4 ★★★ 拦截**引擎内容**的补丁必须加"角色门禁"

- **现象**：用户指出「只有角色是奥卡时才启用」—— 一查是真漏洞：我为欧洛巴斯之触写的
  `TouchOfOrobas.AfterObtained` Prefix **对所有角色生效**，会**拦掉别的角色的起始遗物强化** ✗
  （别的角色的起始遗物**本来就有**先古版本，原始机制对他们是**正确**的）。
- **正确做法**：凡补丁挂在**引擎自己的模型/流程**上，第一件事就是判"这局是不是我们的角色"：
  ```csharp
  if (owner?.Character is not Orca) return true;      // 放行原逻辑
  ```
  判法照抄引擎自己的写法（`NRestSiteCharacter` 里就是 `Player.Character is Necrobinder`）。
  拿不到 Owner/Character 时一律**当作"不是我们的角色"**（宁可不改，也不误改）。
- **推广**：`TouchOfOrobas`、`ArchaicTooth`、各种原版事件/遗物 —— **引擎的东西别人也在用**，
  改动必须**收窄到本角色**（这与 `踩坑指南.md` 里"原版图集染色会污染别的角色"是同一条纪律）。

### 7.8 ★★★ 整段拦截引擎方法 ⇒ **必须补回被跳过的收尾**（本轮最贵的一课）

- **症状**：先古事件选完选项后**卡死**（页面不推进）；而牌发得出来、动画与计数都正常。
- **我们做的**：在 `TouchOfOrobas.AfterObtained` 上挂 Prefix 并 **`return false`（整段跳过）**，
  目的只是"别做那次把起始遗物换成头环的 `RelicCmd.Replace`"。
- **引擎原本的流程**：
  ```csharp
  // AncientEventModel.RelicOption 的 OnChosen 尾部
  await RelicCmd.Obtain(relic2, base.Owner);   // ← 内部 await relic.AfterObtained()
  CustomDonePage = customDonePage2;
  Done();                                      // ★ L249（protected）—— 宣告事件结束
  ```
- **真机制（比"少调一次 Done"更根本）**：`AfterObtained()` 是 **`async Task`**。
  Harmony 的 Prefix 返回 false 时，**方法仍会返回，而返回值是该类型的 default ⇒ `null`** ✗
  ⇒ 调用方 `RelicCmd.Obtain` 里那句 `await relic.AfterObtained()` **await 了 null** ⇒ 抛异常
  ⇒ `OnChosen` 在 `Done()` **之前**中断 ⇒ 事件收尾没人做 ⇒ **卡死**。
- **正确做法（两层，缺一不可）**：
  1. **把 Task 补上**（根治）：Prefix 里 `__result = Task.CompletedTask;` 再 `return false;`
     —— 这样调用方的 `await` 拿到的是"已完成"，不会抛；
  2. **把收尾补上**（本轮采用，已验证可行）：自己调一次引擎的结束宣告
     —— 事件实例走 `EventSynchronizer.GetEventForPlayer(player)`（L327 实据），
     `Done()` 是 `protected` ⇒ 反射调用；**取不到一律记日志**，不静默。
- **推广（本条最值钱）**：**凡是"整段跳过"引擎方法，先问三件事**：
  ① 它的返回类型是什么（`Task`？⇒ 必须补 `__result`）；
  ② 调用方在它**之后**还做了什么（收尾/推进/状态转移都可能因此丢）；
  ③ 我跳过的到底是"一个动作"还是"一个流程里的一环"。

### 7.9 本轮另外两条过程教训（都是我自己踩的）

- **日志会骗人 ⇒ 判据必须先验证**：
  我们打过 `⇒ 获得卡牌【栖途】（已入牌堆，牌组现有 9 张）`，而玩家实际看到的是 10 张 ✗
  ⇒ `result.success` 为真、读到的计数却是错的源。**"日志说成功"不等于成功**；
  打日志的判据本身要先被验证（引用的对象是不是玩家真正看的那个）。
- **改错层 ⇒ 白改两轮**：看到 `Canonical model … used in incorrect place` 就断定"要传实例"，
  把 `.ToMutable()` 加在了**调用方**；而正确分工在 `GrantToDeck` **内部**：
  `RunState.CreateCard(card,…)` 要**模板**（它自己 ToMutable），`CardPileCmd.Add(added,…)` 用**产出实例**。
  引擎里两个异常是**配对**的（`CanonicalModelException` / `MutableModelException`）
  ⇒ 模型层的报错**必须落到具体那一行**再动手，不能靠"应该是这样"。
- **"动画"的正解一直是引擎里的一句 API**（见 §7.10）：我为它去走奖励界面，撞上死锁（§7.1）就撤回了，
  **没有再找** —— 而 `SpecialCardReward.OnSelect()` 里就写着答案。

### 7.10 ★ 卡牌"加入卡组"的动画 = `CardCmd.PreviewCardPileAdd(result, 2f)`

```csharp
// MegaCrit.Sts2.Core.Rewards.SpecialCardReward.OnSelect()（引擎源码）
CardPileAddResult result = await CardPileCmd.Add(_card, PileType.Deck);
if (result.success) { CardCmd.PreviewCardPileAdd(result, 2f); }     // ★ 动画就是这一句
```

- **不弹任何界面、不碰事件流程** ⇒ 不会死锁（对比 §7.1 那条死路）。
- 用户实测：加上它之后「动画有了后是正常的！**卡组数量也对了**」
  ⇒ 说明它同时是"入库流程的收尾"：**少了它，牌只算半个入组**（计数不涨）。
- 秒数 `2f` 用具名常量引用（来源＝引擎那句），避免魔法数散落。

### 7.11 ★★★ 架构纠正（用户一针见血）：**事件 → 遗物 → 效果，只能有一条线**


- **用户原话**：<i>"你事件与欧洛巴斯之触遗物没有连上来。比如说，你事件是给遗物，然后是欧洛巴斯之触遗物去触发，
  现在本末倒置搞出来了 2 条线了"</i>
- **我错在哪**：正确的链路是**一条**——

  ```
  先古事件 ──给出──> 欧洛巴斯之触（遗物）──触发──> 效果（不给头环、改给【栖途】）
  ```

  我却同时在**两端**动手：① 把事件的遗物选项换成卡牌选项 ② 又在遗物 `AfterObtained` 上拦一道
  ⇒ **两条平行线、本末倒置** ✗
- **为什么这条纪律特别重要**（本轮两次卡死的病根都在这）：
  ① 事件那端动手 ⇒ 撞上事件页推进机制（§7.1 死锁 / §7.7 软锁）；
  ② 遗物那端才是**效果该在的地方**，事件只管"给"。
- **正确做法**：**事件端一律不动**（原样给遗物，照样有图标、有它自己的流程），
  只在**遗物的触发点**改效果（`TouchOfOrobas.AfterObtained` 的 Prefix）+ 改文案（§7.5 `bc912da`）。
  ⇒ 代码更少、**根本不碰事件流程**、也不可能软锁。
- **推广**：接引擎的机制时先画一条链（**谁产出 → 谁触发 → 谁承担效果**），
  **只在自己该站的那一环动手**；想"两头都改"时先问一句：这是不是把一件事做成了两件事？
