## 从清单能看出来的几件事（供后续整理参考）

1. **`OrcaEnergyCounter.cs` 602 行是最大的单文件**，且它只做"能量球外观"一件事
   ⇒ 是拆分的第一候选（外观 / 特效 / 补丁三段可分开）。
2. **`Cards-*.cs` 的文件名与内容对应关系不直观**：
   `Cards-Pack2.cs` 与 `Cards-Pack2-B.cs` 是同一卡包却分成两个文件；
   `Cards-Dragon.cs` 里装的是铸血/涅槃之握/践踏（跨体系）。
   ⇒ 若要"按卡包/体系分目录"，这里是主要工作量。
3. **一个文件装多个 Power 是常态**（`OrcaPowers2.cs` 477 行装 4+ 个）
   ⇒ 与项目里"一个卡一个文件"的风格不一致。
4. **`Patches/` 与其它目录的界限是"这个文件是否只做补丁"** —— 但实际上
   `Core/OrcaPoolRegistry.cs`、`UI/OrcaCharacterIcon.cs` 等也含补丁类
   ⇒ 这个界限目前是**约定**而非结构保证。
5. **`OrcaSkin.cs` 的四个骨架访问器**（战斗/选人/商店/篝火）现在三个已接线，
   选人那个确认**不需要**（pck 里没有 `scenes/character_select/orca.tscn`）。
